What the library holds

The software answers one question per node: a price, an orbit period, how long a ring coasts. Nodes are grouped, and the groups sit in layers, joined at one door each.

Layer 1 — the companycases, the catalogue, prices, orders, the facility, standards, and risk management

Layer 3 — subsystemsnot in this library: restricted to the developer team

Each node's page is its document (what it answers, how, from what, how far to trust it) and, once filled and saved, a request to the developer team.

First time here

  1. Find a node: type part of its name below, for example spin-down.
  2. Open it and read the first sentence: it says what the node is for and how far you can trust it.
  3. To ask for anything, fill that page and press “Save filled copy”. Send the saved file to the developer team. They answer in the same file.

Where the library stops being reliable

  • It is a snapshot of one release. A node may have moved on since: a request made from an old copy is sent back (F04).
  • “Not written yet” means the node exists in the tree but answers nothing: every result that needs it is blocked, by name.
  • “Unconfirmed” means nobody has put their name to the relation or the value. The software runs it and says so in every result that reads it.
  • A risk level is the highest open risk any belief about the node carries. The levels are proposals until decision D26.
Common wrong idea
“Filling a node's page changes the software.”
It does not. The page becomes a request. The developer team checks it, implements it, and releases it; only then does the software answer differently. Your saved file is the record of what you asked.

In one line: every node, offline; read it, and to change it, send its filled page.
